## Direct table privileges

At checkpoint, `anon` and `authenticated` had no direct grants on the nine CRM tables. `service_role` had:

`DELETE, INSERT, REFERENCES, SELECT, TRIGGER, TRUNCATE, UPDATE`

on each CRM table.

This is a key security invariant: browser roles must not gain direct CRM table privileges during migration.

## Recovery interpretation

This manifest materially improves recovery confidence because it captures the live structure and security posture even where original 2026-08-13/14 migration SQL is missing.

It still does not replace a genuine full database schema dump. If a trusted `pg_dump --schema-only` or Supabase schema export becomes available, preserve that separately and compare it with this manifest. Do not invent missing historical migration SQL.

For P1 Cloudflare static Preview, this manifest plus the frozen Vercel deployment and live migration ledger is sufficient to detect accidental database drift because P1 is not permitted to modify Supabase at all.
